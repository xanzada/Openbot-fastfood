# 02. Architecture Decision Records (ADR)

> Мақсаты: Барлық маңызды архитектуралық шешімдерді құжаттау. Әрбір ADR — бұл неге, қашан және қандай шешім қабылданғанын түсіндіретін уақыт белгісі.

## Ережелер

1. Әрбір **маңызды** шешім ADR арқылы құжатталады
2. ADR нөмірленеді (ADR-001, ADR-002, ...)
3. ADR **ешқашан өзгертілмейді** — тек superseded деп белгіленеді
4. ADR-дің статусы: Proposed → Approved → Deprecated/Superseded
5. Әрбір ADR-де балама шешімдер салыстырылуы керек

## Қашан ADR жазу керек?

- Жаңа сыртқы жүйе/сервис интеграциясы
- Дерекқор/кэш архитектурасының өзгеруі
- API дизайнының маңызды шешімі
- Security/privacy шешімдері
- Framework/library таңдау
- Deployment архитектурасының өзгеруі
- Жоғары тәуекелді техникалық шешімдер
